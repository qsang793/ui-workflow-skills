# UI Audit — Reminders (2026-10-30)

## Stack
- Framework: Vanilla JS + FastAPI serving one Jinja2 template (`app/templates/index.html`)
- Build tool: none
- CSS: plain CSS in `app/static/styles.css`, plus inline `style=` attributes in the template
- State: none (the server holds an in-memory list; the page re-fetches and re-renders after each change)
- Design tokens: `app/static/styles.css` (`:root` block with 4 variables)
- Run: `uvicorn app.main:app --reload` (run from the project root; inferred from `app/main.py` and `requirements.txt`, no README or Procfile) → http://127.0.0.1:8000

## Pages / Routes (top 10)
Single-page app: one route, three tabs switched client-side.
- `/` — `app/templates/index.html` (route in `app/main.py`)
- Tab "Today" (`#today`) — not-done reminders
- Tab "All reminders" (`#all`) — every reminder
- Tab "Settings" (`#settings`) — notification time field and Save button
- `/api/reminders` (GET) — `app/main.py`
- `/api/reminders/{id}/done` (POST) — `app/main.py`

Components: no component files. Largest file is 35 lines, so no oversized-file issues (nothing over 500 lines).

## Style approach
Styling is split between a small stylesheet and inline `style=` attributes on the body, header, tabs, views and settings form. A `:root` token block exists, but nothing uses it (0 `var(--` references); every color is a hard-coded hex, about 19 unique values, mostly near-duplicate blues and grays.

## Pain points

### 🔴 High
- Not responsive: `<body>` is fixed at `width: 800px`, `.view` at 760px, the input at 300px. There is no `<meta name="viewport">` and no media queries, so it breaks on phones.
- Tokens exist but are unused: `--color-primary`, `--color-success` etc. are defined, yet the same colors are repeated as raw hex (`#2b6cb0`, `#38a169`) inline and in the CSS. This is the highest-leverage fix for a redesign.
- Broken, inaccessible logo: `<img src="/static/logo.png">` has no `alt`, and `logo.png` does not exist in `app/static/`, so it renders as a broken image.
- Unescaped text injected with `innerHTML` (`app/static/app.js`): reminder titles are inserted as raw HTML, so a title containing markup would break the layout or run script. Must be kept in mind when porting the design.
- Settings does nothing real: Save only shows a browser `alert()`; there is no backend endpoint for the notification time. The design must not promise it works.

### 🟡 Medium
- No loading state: both `fetch` calls (`loadReminders`, `markDone`) have no spinner, skeleton or disabled button, and no error handling.
- Tabs lack semantics and feedback: no active-tab highlight, no `role="tablist"`/`aria-selected`, no `aria-` attributes at all; no `<header>`, `<nav>` or `<main>`; no `lang` on `<html>`; the settings input has no `<label>`.
- No empty state: `.empty` is styled but never used, so an empty Today tab is just blank.
- Done reminders still show a "Done" button, and "Today" means "not done", not "due today".
- Inline `style=` used 10 times in a 26-line template, with mixed grays (`#333`, `#444`, `#555`, `#777`) for the same kind of text.

### 🟢 Low
- Hardcoded English text and owner name ("Lan") with no i18n markers.
- `.reminder button` uses `#3182ce`, a third blue next to `#2b6cb0`.
- Inline `onclick="markDone(...)"` handlers instead of event listeners.

## Recommendation
Confirm scenario C: the app is tiny and server-rendered, so keep FastAPI + Jinja and restyle it in place; the design must cover the three tabs, empty/loading states, and the Settings screen's missing backend.
