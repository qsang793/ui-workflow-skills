## Pages / Routes (top 10)
Single-page app: one URL, three client-side tabs.
- `/` — `app/templates/index.html` (page shell, greets "Hello {{ owner }}")
- Tab "Today" (`#today`) — not-done reminders, rendered by `app/static/app.js`
- Tab "All reminders" (`#all`) — every reminder, rendered by `app/static/app.js`
- Tab "Settings" (`#settings`) — notification time field and Save button, in `index.html`
- `/api/reminders` (GET) — `app/main.py`, data for the tabs
- `/api/reminders/{id}/done` (POST) — `app/main.py`, used by the "Done" button

## Style approach
Styling is split between a tiny stylesheet and inline `style=` attributes in the template, which carry the page width, header colours, and the Settings controls. Design tokens are defined but nothing uses them: there are 0 `var(--…)` references, and the same colours are written as raw hex in both files. Across the two files there are about 17 distinct hex colours (3 blues, 4 greys for tab text, two spellings of white).

## Pain points

### 🔴 High
- **Not responsive:** `body` is fixed at `width: 800px`, `.view` at `760px`, and the Settings input at `300px`. There is no `<meta name="viewport">` and no media queries, so the page will not fit a phone.
- **Tokens exist but unused:** `--color-primary`, `--color-success` and `--color-text` are defined, but their values are re-typed as hex (`#2b6cb0`, `#38a169`) in about 10 inline styles and the stylesheet. Wiring these up is the highest-leverage fix for the redesign.
- **Accessibility basics missing:** the logo `<img>` has no `alt`, and `/static/logo.png` does not exist in `app/static`, so it renders as a broken image. There is no `lang` on `<html>`, no `<header>`/`<nav>`/`<main>`, and 0 `aria-` attributes. The tabs are plain buttons with no `role="tab"` or selected state. The tab text greys (`#555`, `#777` on `#fafafa`) are also low contrast.
- **Tabs give no feedback:** nothing marks the active tab, and "Today" shows every not-done reminder, not just those due today. This is a design question for the Stakeholder, but it affects what the screen shows.

### 🟡 Medium
- **No loading, empty or error state:** both `fetch()` calls (`loadReminders`, `markDone`) show no spinner and no disabled button, and they have no error handling. `.empty` is defined in CSS but never used, so an empty list is a blank area.
- **Settings "Save" does nothing real:** it calls `alert("Saved …")`, and there is no API route to store the value. The design should treat Settings as a behaviour the backend does not yet support (flag for `integration-planner`).
- **Unescaped text injected with `innerHTML`:** `r.title` goes straight into the markup, which is a script-injection risk if titles are ever user-entered. Developer note: this belongs with the port, not the design.
- **Completed reminders still show a "Done" button** on the "All reminders" tab.

### 🟢 Low
- Inline `onclick="markDone(...)"` in generated markup instead of event listeners.
- No i18n markers; all text is hardcoded English (fine at this size, relevant only if more languages are wanted).
- Page `<title>` is the generic "Reminders" and there is no favicon.
