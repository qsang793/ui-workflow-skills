# UI Audit — Reminders (2026-10-27)

## Stack
- Framework: Vanilla JS + FastAPI serving one Jinja template (single-page app with client-side tabs)
- Build tool: none (raw HTML/CSS/JS served from `app/static/`)
- CSS: plain CSS in `app/static/styles.css` plus inline `style=` attributes in `app/templates/index.html`
- State: none — data lives in the DOM; reminders are re-fetched after each change
- Design tokens: `app/static/styles.css` (`:root` with `--color-primary`, `--color-success`, `--color-text`, `--space-2`)

## Pages / Routes (top 10)
- `/` — `app/templates/index.html` (the single page, rendered by `app/main.py`)
- Tab "Today" — `#today` view, filled by `loadReminders()` in `app/static/app.js` (shows reminders not yet done)
- Tab "All reminders" — `#all` view, `app/static/app.js` (shows every reminder; done ones are struck through)
- Tab "Settings" — `#settings` view, `app/templates/index.html` (notification time input + Save)
- `GET /api/reminders` — `app/main.py`
- `POST /api/reminders/{reminder_id}/done` — `app/main.py`

## Style approach
There is a small stylesheet that defines four design tokens, but nothing uses them: `var(--` appears 0 times. The colours are typed in directly instead, 16 different ones across 2 files, and 11 inline `style=` attributes in the template override the stylesheet. Each tab button has its own grey (`#333`, `#444`, `#555`), and the "Done" button uses a different blue (`#3182ce`) from the header (`#2b6cb0`).

## Pain points

### 🔴 High
- **Not usable on phones.** There is no `<meta name="viewport">`, the page is fixed at `width: 800px` (`index.html:7`), views at `760px` (`styles.css:9`), the input at `300px`, and there are 0 media queries. On a phone the page shows as a tiny zoomed-out desktop page.
- **Design tokens exist but are never used.** The `:root` tokens in `styles.css` are ignored, and colours are hardcoded in both files instead. Pointing everything at the tokens is the cheapest way to get a consistent look, and it lets a redesign change colours in one place.
- **No loading, error or empty states.** `loadReminders()` and `markDone()` (`app.js:9-29`) show nothing while waiting, never check `res.ok`, and the "Done" button can be clicked many times. An empty list shows a blank area: the `.empty` class is defined but never used.
- **Settings "Save" does nothing real.** It only shows an `alert()` (`app.js:31-33`). The backend has no settings endpoint, so the notification time is never saved. Users will think it worked.

### 🟡 Medium
- **Tabs are not accessible.** They are plain `<button>`s with no `role="tablist"`/`aria-selected`, and the current tab has no visual highlight, so users can't tell which tab they are on. The page has 0 `aria-` attributes and no `<header>`/`<nav>`/`<main>`, and `<html>` has no `lang`.
- **Settings input has no label.** "Notification time" is a `<p>`, not a `<label for>`, and the field is a free-text input instead of `type="time"`.
- **Broken, inaccessible logo.** `<img src="/static/logo.png">` has no `alt`, and `logo.png` does not exist in `app/static/`, so it shows as a broken image.
- **Reminder titles are inserted as raw HTML.** `innerHTML` with `r.title` (`app.js:17-22`) means a title containing HTML will be rendered or executed. Build the rows with `textContent` during the redesign.

### 🟢 Low
- Inline `onclick="markDone(...)"` in generated rows. Use `addEventListener` to match the rest of `app.js`.
- Hardcoded English strings and no i18n setup (fine for now, but worth knowing).
- Dates are shown as raw `2026-11-01` strings, not friendly formats like "Sat, 1 Nov".

## Recommendation
Confirm scenario C. The codebase is tiny (107 lines total, no oversized files) and nothing here needs a stack change. A responsive layout, a cleanup to use the design tokens, and proper states will fix it within the current Vanilla JS + Jinja stack.
