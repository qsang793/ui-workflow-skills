# UI Audit — Reminders (2026-11-02)

## Stack
- Framework: Vanilla JS + FastAPI serving one Jinja2 template (no JS framework, no jQuery/htmx)
- Build tool: none
- CSS: plain CSS in `app/static/styles.css` plus inline `style=` attributes in the template
- State: none (the server list is re-fetched and re-rendered as HTML strings)
- Design tokens: `app/static/styles.css` (`:root` block, 4 tokens, none used anywhere)
- Run: `uvicorn app.main:app --reload` (run from the project root; inferred from `app/main.py`, no README/Procfile) → http://127.0.0.1:8000
- Checks: none found

## Pages / Routes (top 10)
- `/` — `app/templates/index.html` (rendered by `app/main.py`)
  - Tab "Today" (`#today`) — reminders not yet done
  - Tab "All reminders" (`#all`) — every reminder
  - Tab "Settings" (`#settings`) — notification time and Save
- `/api/reminders` — `app/main.py` (JSON, not user-facing)
- `/api/reminders/{id}/done` — `app/main.py` (JSON, not user-facing)

## Style approach
Almost all styling is inline in `index.html` (11 `style=` attributes) with a small `styles.css` (13 lines) beside it. `styles.css` declares colour and spacing tokens, but nothing uses `var(--…)`. About 17 distinct colour values are hard-coded, several near-duplicates (`#fff`/`#ffffff`, three greys `#333/#444/#555` for the same tab buttons, `#2b6cb0` vs `#3182ce` blues).

## Pain points

### 🔴 High
- Not responsive: `body` is fixed `width: 800px`, `.view` is `760px` and the input is `300px`. There is no `<meta name="viewport">` and no media queries, so it breaks on phones.
- Tokens exist but are unused: `--color-primary`, `--color-success` and others are defined, yet the same values are hard-coded in inline styles and CSS. This is the highest-leverage fix for a redesign.
- Broken, inaccessible logo: `<img src="/static/logo.png">` has no `alt`, and `logo.png` does not exist in `app/static/`.
- Tabs and controls are not accessible: tab buttons have no `role="tablist"`/`role="tab"`/`aria-selected`, there are no `<header>`/`<nav>`/`<main>` landmarks, no `<html lang>`, the input has no `<label>`, and the grey-on-grey text (`#777` on `#fafafa`, `#a0aec0` done items) is likely under contrast guidelines.
- Reminder titles are injected via `innerHTML` without escaping (`app/static/app.js`). A title containing HTML would render as markup (an XSS risk once users can add reminders).

### 🟡 Medium
- No loading, error or empty states: `loadReminders()` and `markDone()` have no spinner and no failure handling. `.empty` is styled but never used, so an empty Today tab is just blank.
- Settings "Save" only shows `alert()`; nothing is sent to the backend and the time is not persisted. The design must either drop it or the backend must gain an endpoint.
- No active-tab indicator: clicking a tab shows its view, but the buttons never show which one is selected.
- "Today" means "not done", not "due today" (`app/static/app.js`), which is confusing next to the due dates shown.
- The "Done" button is shown on already-done reminders, and the due date is raw ISO text (`2026-11-01`), with no overdue cue.

### 🟢 Low
- Inconsistent button styling: the tab, Done and Save buttons use three different looks.
- Hard-coded English text throughout, with no i18n markers (fine unless a second language is planned).
- No tests, lint or CI, so there are no automated checks to protect a port.

## Recommendation
Confirm scenario C: the app is tiny (about 100 lines, one page with three tabs) and keeping FastAPI + Jinja + vanilla JS is straightforward. Wire the tokens, fix the layout and accessibility, and decide the Settings behaviour in the design brief.
